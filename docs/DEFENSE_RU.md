# Защита Assignment 06: Visitor

## Что делает программа

Создаёт файловую систему в памяти. FileNode — файл с именем и размером. DirectoryNode — каталог с дочерними узлами. Данные находятся в объектах Java; программа не сканирует настоящий диск.

Три независимые операции: TotalSizeVisitor складывает размеры файлов; SearchVisitor ищет файлы по имени И минимальному размеру; StatisticsVisitor считает файлы, каталоги и максимальную глубину.

## Где Visitor и как объяснить double dispatch

Visitor — поведенческий паттерн, позволяющий добавлять операции над существующими типами объектов через отдельные классы посетителей.

Открой TreeWalker.walk, FileNode.accept и TotalSizeVisitor.visit(FileNode).

1. Walker хранит ссылку Element. Вызов element.accept(visitor) во время выполнения выбирает accept реального объекта: файла или каталога.
2. Внутри FileNode.accept выражение this имеет тип FileNode. Поэтому компилятор выбирает перегрузку visit(FileNode). Затем Java выбирает реализацию этой перегрузки у реального посетителя, например TotalSizeVisitor.

Не говори, что Java выбирает перегрузку по типу аргумента во время выполнения: перегрузка выбирается при компиляции. Два виртуальных вызова accept и visit вместе обеспечивают double dispatch.

Один FileNode с разными посетителями: размер прибавит байты, поиск проверит условия, статистика увеличит число файлов. Один посетитель с разными элементами: файл добавит байты, каталог — нет.

## Порядок работы

walk сначала вызывает reset, кладёт корень в стек с глубиной 0 и пустым путём. Для каждого извлечённого узла задаёт at(path, depth), вызывает accept один раз и кладёт детей в стек. Дети добавляются с конца списка, чтобы извлекаться в порядке вставки. Стратегию поведения по типу узла walker не выбирает.

Только walker обходит дерево. Если добавить обход детей в DirectoryNode.accept или в visit(DirectoryNode), узлы начнут учитываться дважды.

## Как объяснить результаты

Размер: 8192 + 1024 + 256 + 128 + 2048 + 0 + 512 = 12160 байт. Каталоги не имеют собственных байтов. Файлов 7. Каталогов 5: workspace, assets, empty, docs, drafts. Корень входит в число каталогов.

Глубины: workspace = 0; docs = 1; drafts = 2; notes.txt = 3. Максимум 3. Пустые каталоги также учитываются при подсчёте глубины.

Для .txt и 256 подходят notes.txt размером ровно 256 и guide.txt размером 1024. zero.txt не подходит из-за размера. logo.png не подходит из-за имени. Результат сортируется по строковым путям: docs/drafts/notes.txt раньше docs/guide.txt.

Для .md и 128 подходят README.md и docs/drafts/todo.md. Если повысить порог до 129, todo.md исчезнет, README.md останется.

## Инварианты дерева

DirectoryNode.add проверяет всё до изменения коллекции: null, цикл, существующего родителя, повтор имени. Node хранит родителя; внешнего setter нет. rejectCycle поднимается от текущего каталога к предкам и сравнивает ссылки через ==. Это проверка идентичности объектов, а не проверка их классов.

children возвращает List.copyOf. Через этот список нельзя добавить или удалить ребёнка, поэтому невозможно обойти add/remove. Одинаковые имена в разных каталогах разрешены. Имена чувствительны к регистру.

## Вопросы преподавателя

**Зачем Node, если есть Element?** Element — контракт паттерна. Node — абстрактная база для общего имени и контроля родителя. Конкретных типов всё равно два. Sealed ограничивает допустимые реализации, сохраняя инварианты.

**Зачем пустой visit(DirectoryNode) в размере и поиске?** Каталог нужно посетить, но он не является файлом: его размер не прибавляется, в файловые результаты поиска он не включается. Обход его детей выполняет walker.

**Как посетитель узнаёт путь и глубину?** Walker перед каждым accept вызывает at. Относительный путь строится от выбранного корня, не из цепочки глобальных родителей.

**Почему нет stale state?** Каждый walk вызывает reset. Search возвращает неизменяемый снимок, Statistics — record, поэтому новые запуски не меняют старые результаты. Один visitor нельзя одновременно использовать в двух обходах.

**Как добавить новую операцию?** Создать класс-наследник AbstractVisitor, реализовать resetResult, обе visit и result. Commit 89f0ff1 добавил статистику без изменения элементов.

**Как добавить новый тип элемента?** Изменить sealed-иерархию, добавить соответствующий visit в Visitor, реализовать accept нового элемента и обновить все посетители. Это главный компромисс Visitor.

**Чем отличается от Strategy?** Strategy заменяет один алгоритм внутри Context. Visitor добавляет независимые операции над разными существующими типами элементов через accept/visit.

**Почему не instanceof?** Поведение выбирают методы accept/visit и полиморфизм. Проверки if в валидации или поиске разрешены: они не выбирают поведение по классу узла.

**Какая сложность?** Каждый узел посещается один раз. Сортировка m совпадений добавляет O(m log m). Построение строковых путей и память стека также зависят от длины путей. Рекурсивного обхода нет.
